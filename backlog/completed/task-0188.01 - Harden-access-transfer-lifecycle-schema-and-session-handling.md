## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Server-side follow-ups from the TASK-0071.02 review. The transfer lifecycle has two functional gaps: open rejects approved-but-unredeemed transfers so a target that reloads the link cannot redeem, and cancel only works in pending state so the source cannot stop an approved transfer. Data hygiene and schema also need hardening: expired rows are never pruned, approved_request_id has no foreign key, session redemption clears the whole session, and transfer/grant cookies use SameSite=Strict while the base EVCC cookie uses Lax. Keep approval single-use and source-confirmed, keep redemption gated on the target proof and the exact approved request, and keep MongoDB behavior unchanged.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Open now distinguishes approved state: it re-serves the approved request and code only to the browser holding the matching target proof, returns state so the target UI can resume, and never creates requests or authority. Cancel shares the source-nonce authority model of pending cancel; the general expiry/cancelled/redeemed gate already rejects every later transition. Pruning lives in the store layer and runs inside the create-transfer transaction after the event lock, preserving event-first lock ordering; the sweep is global and excludes redeemed rows because grants have no server-side expiry and revoke needs the row. The FK is added by ALTER TABLE after both tables exist (circular with transfer_id FK); cascade delete of a transfer's own requests is safe because the referencing transfer row is removed in the same statement. Session redemption keeps the session-save-inside-transaction rollback guarantee; the failing-session test still proves the transfer is not consumed on save failure. Cookie fix chosen the match-the-base-EVCC path: Lax already never sends cookies on cross-site state-changing requests, and both existing cookie tests assert Lax, so the e2e grant-cookie assertion was updated to match. Stale migrator image initially applied the old migration; rebuilt postgres-test-migrate and reset the test volumes so the edited migration applied fresh. Pre-existing gofmt findings in auth_otp_test.go, event_timed_slots_test.go, and response_utils.go are unrelated and untouched.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Hardened the PostgreSQL access-transfer lifecycle, schema, and session handling per ACs: (1) open on an approved-but-unredeemed transfer re-serves the approved request, code, and approved state to the browser holding that request's target proof, still without granting authority before redemption; source and other browsers are rejected. (2) Source cancel now accepts pending and approved-but-unredeemed transfers, and cancelled transfers reject open, approve, redeem, and repeated cancel. (3) Redemption replaces only the session identity via session.Set without Clear, so unrelated session keys survive. (4) PruneExpiredAccessTransfers deletes past-deadline pending/approved/cancelled transfers together with their cascade-deleted requests, runs automatically inside every transfer-creation transaction, retains redeemed transfers as revocation anchors, and is backed by a partial index on expires_at. (5) The migration (edited in place with user approval) enforces approved_request_id as a foreign key to access_transfer_requests and the Down migration drops both tables in one statement to resolve the circular foreign keys. (6) Transfer and grant cookies now match the base EVCC and owner cookies with SameSite=Lax, documented in code and the compatibility contract. Validation: scoped and full route suites plus postgres package tests pass on the isolated Compose stack with a freshly migrated database (including rejection-matrix and concurrent single-redemption cases); route tests add open-after-approval, cancel-after-approval rejection, pruning-with-anchors, session-key survival, and foreign-key coverage; Firefox browser transfer journeys pass 5/5 with the grant-cookie assertion updated to Lax; Swagger regenerated (swag v1.16.6) and frontend API types regenerated; frontend lint, format, typecheck, build, and unit suite (144 files, 1051 tests) pass; compatibility documentation updated; changed Markdown formatted with npm run format:markdown; graph refreshed.
