## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Move OTP challenge storage from MongoDB `otpCodes` to PostgreSQL while preserving the existing send and verify semantics in `server/routes/auth.go`.

Preserve the ten-minute expiry, the five-attempt lockout, delete-on-success, and delete-existing-before-insert behavior.
Replace the MongoDB TTL index with a PostgreSQL cleanup strategy.
Keep successful authentication resolving an authoritative PostgreSQL account.
Remove the `OtpCodesCollection` runtime usage and TTL index creation.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 OTP send creates a PostgreSQL challenge that replaces any existing challenge for the email and returns the same API behavior.
- [ ] #2 OTP verify enforces the ten-minute expiry and the five-attempt lockout, increments attempts atomically, and deletes the challenge on success or lockout.
- [ ] #3 Expired challenges are cleaned up without depending on a MongoDB TTL index.
- [ ] #4 Authentication still resolves an authoritative PostgreSQL account, and unit or route tests cover send, expiry, wrong code, lockout, and success.
