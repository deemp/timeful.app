## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
First-time sign-in and the first authenticated request both create records: a PostgreSQL account (possibly with a new platform identity) and a retained MongoDB integration document. Under concurrent requests these check-then-create sequences can create duplicate accounts for one email or fail with a duplicate-key error, breaking the duplicate-free account guarantee in FR-121 and ADR-012.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Concurrent first-time sign-ins for the same email resolve to a single PostgreSQL account, or are serialized so that no duplicate account or platform identity is created.
- [ ] #2 Concurrent first authenticated requests for the same account do not fail when creating the retained integration document, and create it at most once.
- [ ] #3 Tests exercise the concurrent paths and assert no duplicates and no failed requests.
<!-- AC:END -->
