## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make PostgreSQL authoritative for folder create/update/delete and folder-event membership for signed-in accounts, covering both new PostgreSQL events and legacy MongoDB events during migration.

Folder operations must be scoped to the owning account and must not expose or authorize another account's folders. Membership must use explicit stable references that remain valid during transition and can later be rewritten to migrated event identities.

Depends on TASK-0190.03.01 for signed-in PostgreSQL events and stable event identifiers.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Folder create/update/delete works in PostgreSQL for signed-in accounts and is scoped to the owning account.
- [ ] #2 An event can be added to and removed from a folder for both a PostgreSQL event and a legacy MongoDB event.
- [ ] #3 Folder reads return the account's folders with their member events using stable identifiers, without duplicates or another account's data.
- [ ] #4 Legacy MongoDB event references are represented explicitly so TASK-0190.06 can rewrite them to migrated PostgreSQL event identities without a permanent legacy-ID map.
- [ ] #5 Focused API tests cover folder CRUD, membership add/remove, cross-account isolation, and both event sources; frontend matching uses the canonical identifier rather than a store-specific field.
