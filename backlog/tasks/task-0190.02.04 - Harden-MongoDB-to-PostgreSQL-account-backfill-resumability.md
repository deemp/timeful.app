## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The account backfill must be safe to interrupt and rerun, and must not loop or partially apply an account unit. Its pagination can re-read the same page, its account and identity writes are not applied as one unit, and preflight, partial-resume, and pre-existing-mapping cases are untested. The migration contract requires each unit to be written atomically and repeated runs to avoid duplicates.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Rerunning an interrupted backfill resumes without duplicating platform identities or accounts.
- [x] #2 Pagination always advances and terminates for every source document, including documents with a zero identifier.
- [x] #3 Each account migration unit is applied atomically with respect to the source cursor.
- [x] #4 Tests cover no-write preflight mode, a pre-existing platform identity without an account, a pre-existing account, and a repeated or interrupted run.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Fix backfill pagination in `server/scripts/20260910_mongo_accounts_to_postgres/main.go`: separate the "no cursor yet" state from a zero ObjectID, advance the cursor only after each account unit has committed, and process a zero-identifier document instead of looping or skipping it.
2. Make `FindOrCreateAccount` apply its platform-identity and account writes in one PostgreSQL transaction so a unit is atomic.
3. Add tests: preflight no-write, pre-existing platform identity without an account, pre-existing account, zero-identifier pagination termination, and repeated/interrupted resume; update the `pageFilter` unit test for the new cursor signature.
4. Run gofmt/go vet and the isolated Compose backend suite; format changed Markdown if any.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
- Pagination had used a zero ObjectID as the "no page read yet" sentinel and skipped zero-identifier documents, so a zero-`_id` source document re-read the first page forever. A separate `hasCursor` flag now distinguishes the two states and the cursor advances only after each unit commits.
- `FindOrCreateAccount` previously wrote the platform identity and the account as two independent statements. It now runs both in one transaction (and reuses an enclosing transaction when the repository is already transaction-scoped), so a failed unit cannot leave an identity without an account.
- Preflight still reports the work without writing; the skip check remains a read of the authoritative account before any write.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Made the account backfill safe to interrupt and rerun and atomic per migration unit.

What changed
- `server/scripts/20260910_mongo_accounts_to_postgres/main.go`: added a `hasCursor` flag so the first page (no filter) is distinct from a legitimate zero ObjectID cursor, which fixes the infinite re-read of the first page for a zero-identifier document. The source cursor now advances only after each unit commits, `migrateAccountUnit` migrates every source document including a zero identifier, and preflight mode reports the work without writing.
- `server/postgres/accounts.go`: `FindOrCreateAccount` now writes the platform identity and the account in one transaction, reusing an enclosing transaction when the repository is already transaction-scoped (the sign-in path), so a failed unit can no longer leak an identity without an account.

Tests
- `server/scripts/20260910_mongo_accounts_to_postgres/main_integration_test.go`: per-test Mongo source database plus PostgreSQL fixture cleanup; `TestMigrateAccountsIsResumableAndIdempotent` (repeated run), `TestMigrateAccountsPreflightDoesNotWrite`, `TestMigrateAccountsAdoptsPreExistingPlatformIdentity` (interrupted identity-only unit), `TestMigrateAccountsSkipsPreExistingAccount`, and `TestMigrateAccountsTerminatesWithZeroIdentifier`.
