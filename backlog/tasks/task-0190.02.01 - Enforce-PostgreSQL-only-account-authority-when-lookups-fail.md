## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
PostgreSQL is the authoritative store for account identity and profile after the account cutover, and retained MongoDB user documents are integration-only. Today profile lookups silently fall back to MongoDB profile fields, or misreport existence, whenever PostgreSQL returns an error. A transient database failure can therefore make a retained document a second source of account truth, which FR-121 and FR-122 forbid. Make lookup and existence checks treat only a genuine not-found as absent, never a database error, and keep the retained document from supplying account authority.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Reading a profile by account identifier or email never returns MongoDB-authored profile fields when PostgreSQL is initialized but the lookup fails for a reason other than no-row.
- [x] #2 Existence checks report a PostgreSQL error distinctly from a not-found result and never treat the error as account-exists or account-missing.
- [x] #3 Explicit pre-cutover behavior for a deliberately uninitialized PostgreSQL pool is documented and is not triggered by runtime lookup failures.
- [x] #4 Tests cover not-found, database-error, and uninitialized cases, and assert that no MongoDB profile value is served as authority.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Classify PostgreSQL lookup outcomes in the db overlay: distinguish a deliberately uninitialized pool and a genuine `pgx.ErrNoRows` from every other error.
2. Make `db.GetUserById`/`db.GetUserByEmail` return nil (never the retained MongoDB profile) on any other PostgreSQL error, while keeping the documented pre-cutover retained-document fallback for the uninitialized pool and the not-found case.
3. Make `accounts.IsNewUser` return `(bool, error)` so an existence check reports a PostgreSQL error instead of account-exists or account-missing, and update `/api/auth/otp/check-email` to return 500 on error.
4. Document the explicit pre-cutover uninitialized-pool behavior in the migration contract.
5. Add tests covering not-found, database-error, and uninitialized cases for profile reads and existence checks, asserting no retained MongoDB profile is served as authority on error.
<!-- SECTION:PLAN:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Made account lookups fail closed so a transient PostgreSQL error can no longer promote the retained MongoDB user document to account authority.

What changed
- `server/db/users.go`: split account resolution into error-aware `accountByExternalUserID`/`accountByEmail` helpers that treat only `pgx.ErrNoRows` as no account and only `postgres.ErrPoolUninitialized` as the documented pre-cutover state. `GetUserById`/`GetUserByEmail` now return nil (logged) on any other PostgreSQL error instead of the retained Mongo profile.
- `server/accounts/accounts.go`: `IsNewUser` now returns `(bool, error)`, returning the PostgreSQL failure instead of treating it as account-exists or account-missing. The retained document is consulted only for the uninitialized pool, a genuine no-row, or the legacy-only existence case.
- `server/routes/auth.go`: `/api/auth/otp/check-email` returns 500 with a distinct error when the existence check fails.
- `server/docs/postgres-core-migration-contracts.md`: documented the explicit pre-cutover lookup behavior and that only the deliberately uninitialized pool, never a runtime failure, selects the retained MongoDB authority.

Tests
- `server/db/users_test.go` covers uninitialized, database-error, and genuine not-found for identifier and email reads; the database-error case asserts no retained profile is returned.
- `server/accounts/accounts_test.go` covers uninitialized, database-error, and not-found for the existence check; the database-error case asserts an error is returned.
- A new test-only closed `pgxpool.Pool` exercises the initialized-but-erroring state without a server.
