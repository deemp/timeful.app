## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
PostgreSQL is the authoritative store for account identity and profile after the account cutover, and retained MongoDB user documents are integration-only. Today profile lookups silently fall back to MongoDB profile fields, or misreport existence, whenever PostgreSQL returns an error. A transient database failure can therefore make a retained document a second source of account truth, which FR-121 and FR-122 forbid. Make lookup and existence checks treat only a genuine not-found as absent, never a database error, and keep the retained document from supplying account authority.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Reading a profile by account identifier or email never returns MongoDB-authored profile fields when PostgreSQL is initialized but the lookup fails for a reason other than no-row.
- [ ] #2 Existence checks report a PostgreSQL error distinctly from a not-found result and never treat the error as account-exists or account-missing.
- [ ] #3 Explicit pre-cutover behavior for a deliberately uninitialized PostgreSQL pool is documented and is not triggered by runtime lookup failures.
- [ ] #4 Tests cover not-found, database-error, and uninitialized cases, and assert that no MongoDB profile value is served as authority.
<!-- AC:END -->
