## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Deliverables
1. PostgreSQL dashboard listing: add postgres.Repository.ListDashboardEvents(ctx, externalUserID) returning non-deleted events the account owns or responded to, with an Owned flag. Ownership resolves through owner_platform_identity_id or owner_external_id; responded resolves through postgres_event_responses joined to event_visitor_identities.platform_identity_id or account_user_id. One row per event.
2. Mixed-store /user/events: refactor routes/user.go getEvents to keep the existing MongoDB owned/responded/attendee logic and its group hasResponded behavior, then merge PostgreSQL dashboard events. Return []any so Mongo models.Event and PostgreSQL maps serialize together. For PostgreSQL events expose the canonical public identifier as _id and shortId (the bare short_id) and set ownerId to the account external id when owned so EventItem owner controls and routing work; responded-only events keep the anonymous owner id.
3. Frontend canonical identifier: add a shared eventPublicId(event) helper that returns the bare 8-char Crockford id for PostgreSQL events (detected from _id) and m_<shortId|_id> for MongoDB events; use it in EventItem routing/copy-link and reuse it in useEventEditing.copyLink.
4. Focused API tests: owned listing, responded listing, mixed-store (Mongo + PostgreSQL), stranger non-visibility, deleted-event exclusion, and no duplicate entries.
5. Regression coverage: an EventItem unit test for the PostgreSQL canonical link and a repo-tracked Firefox e2e spec that signs in, creates a PostgreSQL poll, sees it on the dashboard, opens it, and sees it persist across reload.
6. Checks: go build/vet, isolated backend suite, frontend lint/fmt/typecheck/build/test:unit, focused Firefox e2e, graphify update.

Sequence
- Repository query + route merge.
- Frontend helper + EventItem + unit test.
- API tests.
- Browser spec.
- Full checks.

Risks and constraints
- PostgreSQL and MongoDB own disjoint records, so merged entries cannot duplicate the same event; still return one row per PostgreSQL event.
- Keep the dashboard MongoDB-only when the PostgreSQL pool is deliberately uninitialized; fail rather than silently drop PostgreSQL events when a query errors.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented the mixed-store signed-in dashboard listing.

Server: added postgres.Repository.ListDashboardEvents, which returns one row per non-deleted PostgreSQL event the account owns (owner_platform_identity_id or owner_external_id) or responded to (a response whose account_user_id names the account or whose Event Visitor Identity is associated with the account's platform identity). A response row is required for the responded case, so merely visiting an event never reveals it.

Route: routes/user.go getEvents keeps the unchanged MongoDB owned/responded/attendee logic and group hasResponded behavior, then merges PostgreSQL events as []any. Each PostgreSQL entry exposes its canonical bare short_id as both _id and shortId; ownerId carries the account identifier only for owned events so EventItem owner controls work, and responded-only events stay anonymous. If the PostgreSQL pool is deliberately uninitialized the dashboard stays MongoDB-only; a query failure returns 500 instead of silently dropping PostgreSQL events.

Frontend: added util eventPublicId(event) (bare 8-char Crockford id for PostgreSQL, m_<shortId|_id> for MongoDB) and used it in EventItem routing/copy-link and useEventEditing.copyLink, replacing duplicated logic.

Evidence: TestSignedInDashboardListsPostgresOwnedAndResponded, TestSignedInDashboardMergesMongoAndPostgresEvents, and TestSignedInDashboardExcludesDeletedPostgresEvent cover owned, responded, mixed-store, stranger/unauthorized, no-duplicate, and deleted cases. e2e/specs/timed-event-dashboard-postgres-firefox.spec.ts signs in, creates a PostgreSQL poll, asserts the dashboard link href is /e/<shortId>, opens it, and confirms it survives reload. Frontend checks (lint, fmt:check, typecheck, build, test:unit 1078 passing) and the full isolated backend suite pass; the access-transfer Firefox spec passes 8/8 as a dashboard-load regression.
