## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make PostgreSQL authoritative for signed-in timed and dates-only polls, including creation, account ownership, responses, settings edits, schedule save/clear, archive/unarchive, and deletion.

Signed-in creation must no longer be excluded from PostgreSQL routing while the transition creation flag is enabled. Preserve the account created-events usage counter behavior. Keep the existing transition flag so disabling it still falls back to the legacy MongoDB path; removing the flag is TASK-0190.07.

Depends on TASK-0190.02 for account authority and signed-in session resolution through the legacy account mapping. Legacy MongoDB behavior for unmigrated events must remain unchanged.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A signed-in user creating a supported timed or dates-only poll has it stored in PostgreSQL owned by that user's account, with no MongoDB event document written.
- [ ] #2 Signed-in responses on PostgreSQL events support association, selected-response edits, rename, and deletion, and respect blind availability and owner authority.
- [ ] #3 Signed-in settings edit, schedule save/clear, archive/unarchive, and delete operate on PostgreSQL events and reject unauthorized callers.
- [ ] #4 Creating a poll in PostgreSQL increments the owning account's created-events usage counter, matching legacy behavior.
- [ ] #5 With the transition creation flag disabled, signed-in creation continues to use the legacy MongoDB path unchanged.
- [ ] #6 Focused API tests cover account-owned creation, response association, archive/delete, counter increment, and unauthorized access.
<!-- AC:END -->
