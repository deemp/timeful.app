## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make PostgreSQL authoritative for signed-in timed and dates-only polls, including creation, account ownership, responses, settings edits, schedule save/clear, archive/unarchive, and deletion.

Signed-in creation must no longer be excluded from PostgreSQL routing while the transition creation flag is enabled. Preserve the account created-events usage counter behavior. Keep the existing transition flag so disabling it still falls back to the legacy MongoDB path; removing the flag is TASK-0190.07.

Depends on TASK-0190.02 for account authority and signed-in session resolution through the legacy account mapping. Legacy MongoDB behavior for unmigrated events must remain unchanged.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented the server-side signed-in PostgreSQL event lifecycle.

Routing: postgresCreationEnabled no longer short-circuits signed-in callers; the same supported-kind gate (specific_dates / dow, non-signup) and the POSTGRES_ANONYMOUS_EVENT_CREATION_ENABLED flag govern both anonymous and signed-in creation. Flag removal stays in TASK-0190.07.

Ownership and counter: within the creation transaction, postgresCreateEvent calls FindOrCreatePlatformIdentity for the session external ID, AssociateEventOwner to set owner_platform_identity_id, and IncrementAccountEventsCreated so the counter advances atomically with the row. owner_external_id is set on the inserted event. The creator Event Visitor Identity and owner token issuance are unchanged.

Responses: no response-storage change was required. resolvePostgresVisitor already associates the signed-in account's Event Visitor Identity, so responses remain owner-account associated and recoverable through the session, matching the anonymous compatibility contract's visitor-ownership model.

Tests: server/routes/postgres_signed_in_event_test.go adds TestSignedInPostgresEventLifecycle, TestSignedInPostgresResponseAssociation, and TestSignedInCreationFallsBackToMongoWhenPostgresDisabled. The existing account/event contract router still sets the flag false and was only comment-clarified.

Browser coverage: a dedicated signed-in creation browser journey is TASK-0190.03.04 per the parent task's recorded decomposition; the existing signed-in PostgreSQL access-transfer spec was run with the flag enabled as regression evidence.
<!-- SECTION:NOTES:END -->
