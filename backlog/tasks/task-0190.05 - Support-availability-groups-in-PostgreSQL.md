- Group responses reuse the existing postgres_event_responses table; calendar-derived mode, selected calendars, copied calendar preferences, and manual availability live in the response payload, and the manual availability window lives in the event payload. No second response table is introduced.
- Attendee membership is keyed by invitation email, preserves absent versus explicit false decline state, and resolves to a PostgreSQL account by email where one exists. Retained MongoDB calendar connections resolve through the explicit account mapping (platform_identities.external_user_id) so calendar-derived availability keeps working without making MongoDB a second account authority.
- Group creation reuses the existing POSTGRES_ANONYMOUS_EVENT_CREATION_ENABLED transition flag; no second flag is introduced, and removal stays in TASK-0190.07.
