## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make PostgreSQL authoritative for account creation, lookup, and profiles, integrating the existing platform identity foundation.
Backfill existing MongoDB accounts while retaining calendar connections, provider tokens, and calendar preferences as integration data in MongoDB.
OTP challenge storage remains in MongoDB, but successful authentication resolves a PostgreSQL account.
<!-- SECTION:DESCRIPTION:END -->

- [x] #3 Calendar connection and token-refresh operations and retained friend/log references continue to resolve accounts through an explicit boundary.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Deliverables
1. Add `accounts` schema migration (UUID PK, unique platform_identity_id FK, profile columns) with a case-insensitive email index. Profile columns mirror the contract's field ownership inventory: email, first_name, last_name, picture, has_custom_name, timezone_offset, num_events_created.
2. Extend `server/postgres` with an Account type and repository methods: GetAccountByExternalUserID, GetAccountByEmail, FindOrCreateAccount (idempotent through platform_identities.external_user_id + unique platform_identity_id), UpdateAccountProfile, DeleteAccountByExternalUserID. Add an isolated temp-table migration test.
3. Add `server/accounts`, the explicit boundary between PostgreSQL account authority and retained MongoDB integration documents. It resolves or adopts accounts for sessions, resolves or creates accounts for sign-in (including adopting a legacy Mongo account by email without duplicate identities), and ensures the retained integration document exists.
4. Make `db.GetUserById`/`db.GetUserByEmail` overlay PostgreSQL profile fields onto the retained MongoDB integration document, so existing call sites read profile authority from PostgreSQL while calendar connections, tokens, and preferences remain MongoDB integration data. Add `db.UpdateUserIntegrationFields` and route every calendar/token write through it so profile is not re-authored in MongoDB.
5. Wire `middleware.AuthRequired` and the auth routes: OAuth and OTP sign-in resolve/create a PostgreSQL account and key the session by the account's external_user_id; sign-out; profile read; profile update; user delete; signed-in access transfers continue to use the same external_user_id mapping.
6. Add a resumable, idempotent MongoDB `users` -> PostgreSQL `accounts` backfill script under `server/scripts/` with a pure-mapping unit test. Repeated runs must not duplicate platform identities or accounts.
7. Add isolated route tests covering new and adopted/migrated accounts, repeated backfills/mappings, duplicate/conflicting email mappings, session resolution, and profile authority without MongoDB profile data.

Verification

Sequence
- Schema + repository + repository test.
- Boundary package + db overlay and integration-field writes.
- Middleware and auth wiring.
- Backfill script + unit test.
- Route-level account contract tests, then full backend checks.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Starting implementation after reading the published migration contracts (server/docs/postgres-core-migration-contracts.md), ADR-012, FR-121, FR-122, and QR-012.

Key constraint: the retained MongoDB `users` document remains the integration record keyed by the same legacy account identity (platform_identities.external_user_id). PostgreSQL `accounts` becomes the sole profile authority; no retained document may create, merge, rename, or authorize an account.

Implementation complete; status left In Progress for review and final e2e validation.

Delivered: accounts schema migration (20260910120000_accounts.sql); Account repository and temp-table tests in server/postgres; server/accounts boundary package; PostgreSQL profile overlay with integration-only writes in server/db/users.go; middleware/route wiring for OAuth, OTP, existing-session adoption, profile read/update, sign-out, and user delete; Mongo->PostgreSQL backfill script with pure and integration tests.

AC evidence (isolated Compose stack): TestAccountRepositoryIsIdempotentAndLinksExistingIdentity and TestMigrateAccountsIsResumableAndIdempotent cover AC1; TestAccountOtpSignInUsesPostgresAuthority and TestAccountExistingSessionAdoptionResolvesAccount cover AC2; TestAccountExistingSessionAdoptionResolvesAccount confirms calendar integration resolves through the boundary for AC3; the repository, route, and script tests cover AC4.
