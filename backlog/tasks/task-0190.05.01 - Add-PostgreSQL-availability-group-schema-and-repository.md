## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement the PostgreSQL persistence layer for availability groups: extend the event-kind constraint to admit the `group` kind and add attendee membership storage, then add repository operations for membership and decline state. Attendee membership is keyed by invitation email and preserves the distinction between absent and explicit false decline state; an email resolves to an account where one exists. Group responses reuse the existing PostgreSQL response storage rather than adding a second response table, so calendar-derived mode, selected calendars, copied calendar preferences, and manual availability stay in the response payload, and the manual availability window stays in the event payload. Do not add route behavior in this subtask.

Schema targets follow server/docs/postgres-core-migration-contracts.md (Availability Group Fields and Attendees And Invitations). Legacy Mongo attendee and event identifiers are rewritten during TASK-0190.06 rather than preserved as a runtime map.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented the PostgreSQL availability-group persistence layer with no route behavior. Schema migration 20260910160000_availability_groups.sql extends postgres_events_type to admit group and creates event_attendees (event_id FK ON DELETE CASCADE, non-empty email, nullable account_user_id, nullable declined, timestamps) with a unique (event_id, email) index and an account_user_id index. account_user_id deliberately stores the resolved legacy external account identifier as text (no cross-database FK), matching folders.account_user_id and postgres_events.owner_external_id conventions; deletion releases it to NULL rather than deleting the email-keyed membership.

Repository additions in server/postgres/attendees.go: Attendee type plus AddAttendee (case-insensitive email-to-account resolution, upsert keyed by event+email), ListAttendees, GetAttendeeByEmail, SetAttendeeDeclined (covers decline and undecline), and RemoveAttendee. The upsert preserves an existing membership identity and its absent-versus-false decline state. accounts.go deleteAccountAuthority now nulls account_user_id for the deleted account so group invitee lists survive.

Group responses need no new table: they use postgres_event_responses with calendar-derived mode, selected calendars, copied calendar preferences, and manual availability in the response payload and the manual availability window in the event payload (per the contract). AC4 is covered by TestGroupResponseReusesResponseStoragePayload.

Tests: added postgres/attendees_test.go (group kind constraint, unsupported kind rejection, membership relation and duplicate uniqueness, absent-vs-explicit-false decline, decline/undecline/removal lifecycle, case-insensitive email resolution and unknown-email NULL, account-deletion release, response storage reuse). Wired the migration into the accounts and signup temp-table harnesses; the signup test's group-rejection assertion now uses a genuinely invalid kind. Full isolated suite passes.

DoD notes: no Markdown files changed, so format:markdown was not applicable. No route behavior was added, so browser e2e coverage is deferred to TASK-0190.05.04 as planned. gofmt is clean for changed files (three pre-existing unformatted files were left untouched); go vet ./... is clean.
