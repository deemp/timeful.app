## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement the PostgreSQL persistence layer for availability groups: extend the event-kind constraint to admit the `group` kind and add attendee membership storage, then add repository operations for membership and decline state. Attendee membership is keyed by invitation email and preserves the distinction between absent and explicit false decline state; an email resolves to an account where one exists. Group responses reuse the existing PostgreSQL response storage rather than adding a second response table, so calendar-derived mode, selected calendars, copied calendar preferences, and manual availability stay in the response payload, and the manual availability window stays in the event payload. Do not add route behavior in this subtask.

Schema targets follow server/docs/postgres-core-migration-contracts.md (Availability Group Fields and Attendees And Invitations). Legacy Mongo attendee and event identifiers are rewritten during TASK-0190.06 rather than preserved as a runtime map.
<!-- SECTION:DESCRIPTION:END -->
