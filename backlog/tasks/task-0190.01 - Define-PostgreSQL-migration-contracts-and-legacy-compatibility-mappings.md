## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Inventory MongoDB collections, embedded fields, SQL schemas, and all consumers before changing persistence.
Document authoritative-store boundaries for the parent task and a staged backfill/cutover strategy.
Read requirements authoring instructions before changing canonical requirements.

Agreed contract decisions:
- Accounts resolve through platform_identities.external_user_id (legacy Mongo user _id hex); migrated entities receive new PostgreSQL identities and all relationships are rewritten during migration, so no permanent legacy-ID map table is required.
- Public event URLs may change at cutover; account identity, ownership, folder membership, and other persisted references must remain authoritative and non-duplicated.
- Legacy guest edit tokens and ambiguous ownership are quarantined and never imported as PostgreSQL authority.
- Cutover uses a resumable batched backfill followed by a short write freeze; no permanent dual writes; MongoDB source data stays intact for rollback.
- This task is documentation and canonical-requirement authoring only; it adds no runtime code, schema, or migration tooling.
<!-- SECTION:DESCRIPTION:END -->
