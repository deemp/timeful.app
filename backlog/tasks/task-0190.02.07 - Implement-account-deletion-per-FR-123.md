## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement the account deletion behavior that docs/requirements/functional/fr/FR-123.md defines so the system has one ratified deletion contract instead of the current split between the UI promise, the AC wording, and the route implementation.

Context
The Settings delete-account action currently calls DELETE /api/user, which removes the PostgreSQL account row and the retained MongoDB integration document, then clears the session. It leaves the platform identity mapping behind, does not release ownership of the events the account organized, and performs no cleanup of the visitor's own responses, friend requests, folders, or historical logs. The two-store delete is not atomic, is not idempotent, and a concurrent account backfill can recreate an account that is being deleted. The UI copy "All your account data will be lost" does not match the actual outcome.

Ratified behavior (FR-123)
- A signed-in visitor confirms deletion by entering the account email address.
- Deletion is immediate and permanent: the visitor is signed out, the account profile and platform identity mapping are removed, and every calendar connection and its provider credentials are disconnected.
- Events the account organized survive with ownership released and keep their other guests' responses.
- The deleted visitor's own responses, friend requests, folders, and historical user logs are removed.
- No data is retained, recovered, or exported after deletion.
- Signing in with the same email afterward creates a new account and a new platform identity.
- Deletion is atomic and idempotent across stores.

Scope
- Rework the delete path in server/routes/user.go, server/accounts, server/postgres, and server/db so the ratified behavior is applied as one unit.
- Remove the platform identity mapping and ensure a fresh sign-in cannot resurrect the deleted account or leave an orphan identity.
- Release ownership on events the account owned while preserving those events and other guests' responses.
- Remove the visitor's own responses, folders and memberships, friend requests, and historical logs.
- Make the delete atomic across PostgreSQL and MongoDB and safe to retry.
- Prevent a concurrent account backfill from recreating an account that is being deleted.
- Update the Settings delete-account copy to describe the ratified outcome.
- Add regression tests for each behavior, including the partial-failure and concurrent-backfill cases.

Do not expand into the unrelated account contract test coverage of TASK-0190.02.06; that task consumes this behavior once it lands.
