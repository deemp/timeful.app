## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Fourth delivery subtask of TASK-0071, depends on TASK-0071.06. Adopt the PostgreSQL identity boundary in the frontend: decode and encode eventVisitorId and opaque response public_ids in the transport layer, persist a per-event non-authorizing eventVisitorId in browser-local storage that survives sign-out, key response selection by opaque public_id, and send current Event Visitor Identities for association at sign-in. Keep the MongoDB guest-credential flow untouched.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 transport.ts decodes and encodes eventVisitorId and opaque response public_ids at the transport boundary only, consumed through the event and response boundary composables
- [ ] #2 A per-event eventVisitorId is persisted in browser-local storage, retained across sign-out and browser sessions until browser-local data is cleared, is non-authorizing, and is never a raw Platform Identity value (FR-073)
- [ ] #3 PostgreSQL response selection and editing are keyed by the opaque response public_id instead of authUser._id or display names
- [ ] #4 Sign-in sends the current browser Event Visitor Identities for Platform Identity association
- [ ] #5 MongoDB guest-credential flow (guestOwnershipCollection, guestId/guestEditToken) is unchanged
- [ ] #6 Frontend lint, typecheck, build, and unit tests pass
