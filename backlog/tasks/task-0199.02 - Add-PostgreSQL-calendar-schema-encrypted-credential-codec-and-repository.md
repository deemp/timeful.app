## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add the PostgreSQL schema, encrypted credential codec, and repository for calendar integrations that currently live on the retained MongoDB `users` document.

Cover calendar account identity keyed by platform identity, provider type, email, picture, enabled state, sub-calendars and their enabled state, and the calendar preferences (`calendarOptions`, primary account key, OAuth token origin).
Encrypt provider credentials (OAuth2 access/refresh/scope, Apple credentials, ICS credentials) at rest using the existing AES-GCM helper and `ENCRYPTION_KEY`, per the contract from TASK-0199.01.
Keep PostgreSQL access in server/postgres; route handlers and services must not access PostgreSQL directly.
Preserve absent-versus-explicit-false semantics and the existing email/calendar-type key behavior.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A goose migration adds PostgreSQL tables for calendar accounts, encrypted provider credentials, sub-calendars, and calendar preferences, with constraints and indexes that preserve existing key and enabled semantics.
- [ ] #2 A repository in server/postgres exposes create, read, update, and delete for calendar accounts and preferences, and no route handler or service accesses PostgreSQL directly except through the repository.
- [ ] #3 Provider credentials are encrypted at rest with the existing AES-GCM helper and are never returned through the API; decryption failures surface as errors rather than empty credentials.
- [ ] #4 Unit tests cover credential round-trip encryption, absent-versus-false enabled and preference fields, and sub-calendar add/remove/update.
