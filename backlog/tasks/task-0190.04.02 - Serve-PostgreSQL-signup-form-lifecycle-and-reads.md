3. ## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented PostgreSQL signup-form lifecycle and reads. Server changes: routes/postgres_event_routes.go and postgres/dashboard.go; tests in routes/postgres_signup_test.go.

Routing: postgresCreationEnabled now admits isSignUpForm payloads (still gated by POSTGRES_ANONYMOUS_EVENT_CREATION_ENABLED). postgresCreateEvent stores type `signup`, keeps isSignUpForm in the payload, strips inline blocks from the payload, and persists supplied blocks through ReplaceSignupBlocks in the creation transaction. The create response now includes shortId alongside eventId and eventVisitorId, matching the legacy public shape (an existing signup e2e spec reads shortId).

Read translation: postgresEventModel maps the `signup` storage kind back to the legacy wire type `specific_dates` and sets isSignUpForm=true, which the frontend uses for signup routing/rendering.

Reads: postgresGetEvent emits signUpBlocks (PostgreSQL UUID as _id, RFC3339 start/end) and signUpResponses keyed by account hex or canonical guest name. It reuses populateSignUpResponsePayloadIdentity and shouldExposeGuestSignUpResponsePayload, strips sensitive user fields, and applies collectEmails+owner email visibility. Blind-availability behavior stays at legacy parity (numResponses omitted for a non-owner; signup responses not privatized).

Edits: postgresEditEvent extracts signUpBlocks from the raw body before binding because PostgreSQL UUID block IDs cannot decode into models.SignUpBlock.Id (a primitive.ObjectID). It persists the ordered set via ReplaceSignupBlocks only when signUpBlocks is present, so an omitted list preserves existing blocks (legacy BSON omitempty behavior), and it keeps type=signup while the payload carries the wire type.

Lifecycle/authorization: archive/unarchive and deletion already route through postgresArchiveEvent/postgresDeleteEvent and work for the signup kind. Response mutation (POST/DELETE /response and /rename-user) is guarded with postgresEventRouteUnavailable for signup events so this subtask never writes signup data into postgres_event_responses; TASK-0190.04.03 replaces the guard.

Dashboard: ListDashboardEvents now also surfaces an event where the account has an event_signup_responses row (account_user_id or associated visitor identity), so signup authorship appears on the signed-in dashboard.

Checks run: cd server && go build ./... and go vet ./... pass. Full isolated suite `docker compose --env-file .env.test -f compose.yaml -f compose.test.yaml run --rm server-route-test` passes (all packages). E2E: `E2E_POSTGRES_ANONYMOUS_EVENT_CREATION_ENABLED=true npm run test:e2e -- --project=chromium-desktop --workers=1 specs/sign-up-form-event.spec.ts` passes 1/1, and `E2E_POSTGRES_ANONYMOUS_EVENT_CREATION_ENABLED=true npm run test:e2e -- --project=firefox-desktop --workers=1 specs/timed-event-dashboard-postgres-firefox.spec.ts` passes 1/1. graphify update . completed.
