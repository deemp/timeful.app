## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement the approved PostgreSQL-only cross-device access behavior after TASK-0071 delivers Event Visitor Identity ownership, EVCC authority, opaque response selection, and blind-availability filtering. The event-page action continues access on another browser through a five-minute pending link, target-displayed matching code, and source approval. It transfers a normal signed-in platform session or a distinct Granted EVCC without changing source ownership. MongoDB behavior and credentials remain unchanged.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The PostgreSQL event page presents one Continue on another device action and states the five-minute matching-code process
- [ ] #2 Opening a copied link creates a pending target-browser request displays a matching code and grants no authority until the source approves that exact code
- [ ] #3 An approved signed-in transfer issues a normal authenticated session for the source Platform Identity on the target browser
- [ ] #4 An ordinary anonymous PostgreSQL transfer requires source EVCC proof and issues a distinct Granted EVCC that authorizes the source Event Visitor Identity response authority without transferring ownership
- [ ] #5 An anonymous event-owner transfer additionally requires Event Owner Edit Token proof and issues a Granted EVCC preserving all owner powers without transferring ownership
- [ ] #6 Granted EVCCs remain usable until target browser data is cleared or the source revokes them and a revoked credential is rejected on subsequent use
- [ ] #7 When a target browser with a Granted EVCC signs in the system requests explicit confirmation before associating the source Event Visitor Identity with the Platform Identity
- [ ] #8 Expired cancelled reused code-mismatched unapproved unauthorized and revoked transfers are rejected
- [ ] #9 MongoDB persistence request behavior and credentials remain unchanged
- [ ] #10 Repository route frontend unit and browser regression coverage verifies both transfer modes blind-availability boundaries and every specified rejection case
- [ ] #11 Relevant API and user-facing documentation reflects the delivered transfer behavior
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Persist five-minute PostgreSQL transfers and independent target requests with hashed browser proofs; serialize approval, redemption, cancellation and grant revocation.
2. Add PostgreSQL-only source/target APIs using normal sessions for signed-in transfers and separate HttpOnly Granted EVCC cookies for anonymous transfers, retaining the target Event Visitor Identity and source ownership.
3. Extend response/owner authorization and explicit confirmed association to separate grants; retain base-credential and MongoDB behavior.
4. Add event-page source controls, target matching-code page and explicit association confirmation through a typed transport boundary.
5. Verify repository and route rejection/privacy coverage, frontend unit tests and isolated Firefox journeys; regenerate API documentation, update compatibility documentation, run required checks and refresh graph.
