## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Route all calendar integration reads and writes to the PostgreSQL repository added in TASK-0199.02 and stop serving calendar fields from the retained MongoDB `users` document.

Update sign-in (`server/routes/auth.go`), the add/remove/toggle/toggle-sub-calendar and calendar-options handlers (`server/routes/user.go`), token refresh (`server/services/auth/auth.go`), calendar fetching (`server/services/calendar/calendar.go`), contact search (`server/services/contacts/contacts.go`), and the middleware/account overlay (`server/middleware/auth.go`, `server/db/users.go`).
Preserve the existing API response shape and key semantics so the frontend is unaffected.
No PostgreSQL failure may fall back to the retained MongoDB document for calendar authority.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Sign-in, add/remove/toggle calendar account, toggle sub-calendar, and calendar-options endpoints read and write calendar integrations only through the PostgreSQL repository.
- [ ] #2 Token refresh updates encrypted access tokens and expiry in PostgreSQL and no longer writes the retained MongoDB document.
- [ ] #3 Calendar event fetching and contact search resolve credentials from PostgreSQL.
- [ ] #4 The middleware and account overlay no longer load calendar fields from MongoDB; the API response shape stays compatible with the frontend.
- [ ] #5 Unit and route tests cover add, toggle, remove, refresh, and options against the PostgreSQL store.
<!-- AC:END -->
