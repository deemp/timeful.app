## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
First delivery subtask of TASK-0071. Add the PostgreSQL-only identity schema and repository layer that the rest of the foundation builds on: private Platform Identities (PVI), event-scoped Event Visitor Identities (EVI), hashed EVCC storage, and Event Visitor Identity-owned responses with composite integrity and opaque public response IDs. Backfill existing PostgreSQL response rows. MongoDB remains untouched.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A PostgreSQL migration creates platform_identities, event_visitor_identities, and event_visitor_credentials relations with UUIDv7 internal identifiers, an opaque non-authorizing public eventVisitorId on event_visitor_identities, and credential values stored only as hashes
- [ ] #2 postgres_event_responses gains a NOT NULL event_visitor_identity_id with a composite (event_id, event_visitor_identity_id) foreign key such that database integrity rejects an event and owner Event Visitor Identity mismatch
- [ ] #3 postgres_event_responses gains an opaque response public_id used as the public response identifier
- [ ] #4 Existing PostgreSQL guest, account, and legacy name-keyed response rows are backfilled to Event Visitor Identity ownership without data loss; account rows find-or-create private Platform Identities from their external Mongo user id strings
- [ ] #5 server/postgres repository methods support identity, credential, and EVI-owned response persistence and lookups, including lookups by opaque response public_id
- [ ] #6 MongoDB persistence, request behavior, and guest credentials remain unchanged
- [ ] #7 Repository and route test coverage verifies the migration, backfill integrity, composite constraint rejection, and MongoDB non-regression
<!-- AC:END -->
