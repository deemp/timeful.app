## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The account contract tests cover OTP sign-in, existing-session adoption, and duplicate emails, but not the OAuth provider name precedence, existence checks, user deletion, integration-field writes, usage-counter increments, or email-based overlays. Add coverage so the acceptance criteria for account resolution across OAuth and OTP, and for account resolution through the integration boundary, have direct objective evidence.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Provider sign-in preserves a user's custom name and otherwise applies the provider name and picture.
- [x] #2 Existence checks report new, existing, and legacy-only accounts correctly.
- [x] #3 Deleting a signed-in account removes the account authority, the account profile, the retained calendar integration document, and the platform identity mapping, while retained events survive with ownership released and other guests' responses intact.
- [x] #4 Calendar add, remove, and toggle, and calendar-options writes change only integration fields and preserve the PostgreSQL profile.
- [x] #5 Event creation and event import increment the account usage counter.
- [x] #6 Email-based account overlay returns PostgreSQL profile values and never MongoDB profile values.
- [x] #7 The added regression tests fail against the behavior addressed by the dependent fix tasks.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Blocked on TASK-0190.02.07. The original AC3 (deletion leaves retained integration and identity records) contradicted the route implementation, the Settings copy, and the migration contract, which governs migration retention rather than user-initiated deletion. The gap was escalated to docs/requirements/functional/fr/FR-123.md and TASK-0190.02.07, which defines and implements the ratified deletion behavior. This task consumes that behavior once it lands and must not implement it directly.

Added the expanded account contract coverage. New `server/routes/accounts_contract_expansion_test.go`: provider-name precedence through a mocked Google OAuth sign-in (AC1); existence checks for new, existing, and legacy-only accounts plus a fail-closed PostgreSQL-error case (AC2); calendar add, toggle, calendar-options, and remove writing only retained integration fields while preserving the PostgreSQL profile (AC4); and event creation plus event import incrementing the usage counter, with the profile counter staying authoritative after the MongoDB events are removed (AC5).

Added `TestGetUserByEmailOverlaysPostgresProfileNotRetained` to `server/db/users_test.go`: the email and identifier overlays return PostgreSQL profile values including the usage counter, and a PostgreSQL error returns nil instead of the retained MongoDB profile (AC6).

AC3 is already covered by the deletion regression tests added with TASK-0190.02.07: `TestAccountDeletionRemovesAccountAcrossStores` and the repository deletion/ownership-release tests assert the account authority, profile, retained integration document, and platform identity are removed while events survive with ownership released and other guests' responses intact.

AC7 verified by temporarily reverting the dependent fixes: the AC2 fail-closed test, the AC5 counter-authority assertion, and the AC6 error-fallback assertion each fail against the pre-fix behavior and pass again after restoring `server/accounts/accounts.go`, `server/routes/user.go`, and `server/db/users.go`.

Checks: gofmt clean; `go vet ./...` clean; the full isolated `server-route-test` `go test ./... -count=1` passes; `npm run format:markdown:check` passes. No runtime, deployment, or browser surface changed, so browser e2e is not required and DoD #3 is satisfied vacuously.
