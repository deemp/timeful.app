## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The account contract tests cover OTP sign-in, existing-session adoption, and duplicate emails, but not the OAuth provider name precedence, existence checks, user deletion, integration-field writes, usage-counter increments, or email-based overlays. Add coverage so the acceptance criteria for account resolution across OAuth and OTP, and for account resolution through the integration boundary, have direct objective evidence.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Provider sign-in preserves a user's custom name and otherwise applies the provider name and picture.
- [ ] #2 Existence checks report new, existing, and legacy-only accounts correctly.
- [ ] #3 Deleting a signed-in user removes account authority while leaving retained integration and identity records per the contract.
- [ ] #4 Calendar add, remove, and toggle, and calendar-options writes change only integration fields and preserve the PostgreSQL profile.
- [ ] #5 Event creation and event import increment the account usage counter.
- [ ] #6 Email-based account overlay returns PostgreSQL profile values and never MongoDB profile values.
- [ ] #7 The added regression tests fail against the behavior addressed by the dependent fix tasks.
<!-- AC:END -->
