## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented PostgreSQL signup response mutation with the explicit-selection and EVCC authority model.

Backend (server/routes/postgres_event_routes.go):
- postgresMutateResponse now resolves the visitor before branching and delegates signup events to postgresMutateSignupResponse instead of returning 501.
- postgresMutateSignupResponse enforces the shared createResponse/responseId guard: create requires proven visitor authority and is owned by the calling Event Visitor Identity; save/rename/delete carry the opaque responseId and require visitor.controls (EVCC or associated account). It uses CreateSignupResponse / UpdateSignupResponse / DeleteSignupResponse, so num_responses is untouched and capacity is reserved atomically under the event row lock.
- Account respondents (session external user id) persist respondent_kind=account with account_user_id; anonymous respondents persist respondent_kind=guest with the shared canonical guest name. Updates preserve the stored respondent kind. Rename validates through respondents.ValidateGuestName and can rename both kinds.
- read: postgresSignupResponses takes the resolved visitor, computes server-proven canEdit from visitor.controls and archive state, and emits the opaque publicId on every entry. RawSignUpResponse gains publicId/canEdit.
- postgresMutationError maps ErrSignupBlockNotFound to 400 signup-block-not-found, ErrSignupCapacityExceeded to 409 signup-slot-full, and keeps the existing duplicate-name unique-violation mapping.

Frontend:
- responseSubmissionBoundary adds encodeVisitorSignUpResponseSubmission (createResponse/responseId + signUpBlockIds).
- useEventRespondent.signUpForBlock branches on event.eventVisitorId: PostgreSQL events submit the explicit-selection payload with withEventVisitorIdentity and remember the returned responseId; legacy Mongo signup forms keep the name-based payload.
- RawSignUpResponse exposes publicId/canEdit; api.ts regenerated from updated swagger annotations after adding the signup contract description and 409 failure.

Tests:
- server/routes/postgres_signup_test.go covers account create/update/delete, guest create/update/rename/delete, canEdit/publicId exposure, unauthorized mutation via a public eventVisitorId, ambiguous-selection rejections, duplicate guest-name error, capacity rejection, and foreign block rejection.

Checks: cd server && go build ./... and go vet ./... pass. The full isolated `server-route-test` suite passes (all packages). E2E `E2E_POSTGRES_ANONYMOUS_EVENT_CREATION_ENABLED=true npm run test:e2e -- --project=chromium-desktop specs/sign-up-form-event.spec.ts` passes 1/1. Frontend lint, fmt:check, typecheck, build, and test:unit (1081 tests) pass. graphify update . completed. No repository Markdown was authored; DoD #4 is not applicable to MCP-managed task records.
