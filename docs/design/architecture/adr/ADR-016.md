# ADR-016: PostgreSQL Owns Retained Calendar, OTP, And Daily-Log Data And Friend Requests Are Retired

## Context

[ADR-011](ADR-011.md) made PostgreSQL authoritative for core records while MongoDB retained calendar connections and provider tokens, calendar preferences, OTP challenges, friend requests, and historical daily user logs.
TASK-0199 moves those retained data kinds to PostgreSQL, retires the dormant friend-request storage, and removes MongoDB entirely.
ADR-011's retained-integration boundary is therefore overturned, while its single-authority principles remain correct and must survive the change.

## Considered Options

- Keep MongoDB as a permanent second store for integrations and supporting data.
- Keep friend requests and migrate them alongside calendar data.
- Move calendar integrations, OTP challenges, and daily logs to PostgreSQL, retire friend requests, and remove MongoDB, preserving the single-authority principles.
- Move only calendar integrations and leave OTP, logs, and MongoDB in place.

## Decision Outcome

Chosen option: "Move calendar integrations, OTP challenges, and daily logs to PostgreSQL, retire friend requests, and remove MongoDB, preserving the single-authority principles", because it removes the cross-store join and the second store without weakening the invariants those stores were protecting.

This decision carries forward and restates the principles from [ADR-011](ADR-011.md):

- PostgreSQL is authoritative for accounts, profiles, all event kinds, responses, attendees, signup data, availability groups, folders, and folder membership.
- Exactly one authoritative store exists per record kind, there is no permanent dual write, and no retained document may create, merge, rename, or authorize an account.
- Account references resolve through `platform_identities.external_user_id`, and migrated records receive fresh PostgreSQL identities as decided in [ADR-012](ADR-012.md).

This decision changes the retention boundary:

- Calendar connections, encrypted provider credentials, sub-calendars, and calendar preferences become PostgreSQL-owned and resolve their account through `platform_identities.external_user_id`.
- OTP challenges move to PostgreSQL with their expiry and lockout semantics, and grant no account authority.
- Historical daily user logs and their memberships move to PostgreSQL.
- `friendrequests` is dormant storage, so it is retired rather than migrated, and no PostgreSQL table replaces it.
- Event-creator and active-user reporting read PostgreSQL records that the core migration already owns, so no reporting data is copied again.
- Once a kind is cut over, its retained MongoDB document is recovery source only and is never read as a second authority.

[ADR-011](ADR-011.md) is superseded by this decision.
The changes take effect per record kind as the retained-data cutover defined by [PostgreSQL Retained-Data Migration Contracts](../../../../server/docs/postgres-retained-data-contracts.md) completes.

## Consequences

- Good, because requests that combined core and integration data no longer join across two stores.
- Good, because one store simplifies backup, retention, and operational recovery.
- Good, because dormant friend-request storage is removed instead of carried forward.
- Bad, because the retained MongoDB source must be migrated, reconciled, and verified per kind before it can be removed.
- Bad, because provider credentials change at-rest format and depend on a correctly configured encryption key.
- Bad, because removing MongoDB is irreversible once the retention window and validation complete.
