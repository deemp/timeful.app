# FR-121: Serve Migrated Core Records From A Single Authoritative Store

Once a core record kind is migrated, the system shall serve that kind's reads and writes from exactly one authoritative store.
Core record kinds are accounts and profiles, [Timed Events](../../../terminology/glossary.md#timed-event), [Dates-Only Events](../../../terminology/glossary.md#dates-only-event), day-of-week events, availability groups, signup forms, [Event Responses](../../../terminology/glossary.md#event-response), attendees, folders, and folder membership.

For a migrated kind, the retained MongoDB documents are recovery-source data and shall not be read as a second authority or used to create, merge, or re-authorize a record.
Each migrated account reference shall resolve to exactly one account identity, and repeating a migration shall not create a duplicate account or a duplicate core record.

Reconciliation evidence on representative migrated fixtures shows one authoritative value per migrated record, no duplicate account identity for a legacy account, and no record authored in two stores after its migration.
