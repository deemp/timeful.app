# QR-013: Protect Provider Credentials At Rest And Keep Them Out Of Responses

## Source

The server stores and serves calendar provider credentials for a [Calendar Connection](../../../terminology/glossary.md#calendar-connection).

## Stimulus

A calendar connection persists an OAuth2 access token, an OAuth2 refresh token, an Apple password, or an ICS feed URL, and a later request or an operator reads the stored records.

## Environment

The authoritative PostgreSQL calendar store after the retained-data cutover, with the provider credentials encrypted under a configured key, and the calendar API serving calendar data to a signed-in account.

## Artifact

Stored provider credentials, the credential decryption path, and calendar API responses.

## Response

The system shall store each provider credential as authenticated ciphertext that cannot be read without the configured key.
The system shall detect modified ciphertext and fail the decryption rather than return a corrupted or empty credential, and shall never substitute the retained MongoDB value.
The system shall not return an access token, a refresh token, an Apple password, or an ICS feed URL through any API response.

## Response Measure

Inspection of the stored credential records shows only versioned ciphertext with no plaintext secret.
A test that modifies stored ciphertext observes a decryption error rather than a credential.
Calendar API response fixtures and response schemas contain no access token, refresh token, Apple password, or ICS feed URL.
